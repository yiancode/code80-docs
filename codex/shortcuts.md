# Codex CLI 快捷键

Codex CLI 的官方公开资料对交互快捷键说明相对克制，日常使用时主要遵循终端默认行为。因此，这一页只保留常用且稳定的操作，适合当作速查表使用。

## 常用快捷键

| 场景 | 快捷键 / 操作 | 说明 |
|------|---------------|------|
| 取消当前步骤 | `Ctrl+C` | 中断当前生成、命令执行或正在进行的任务 |
| 退出当前会话 | `Ctrl+D` 或直接退出终端 | 结束当前 Codex CLI 会话 |
| 清屏 | `Ctrl+L` | 清空当前终端显示，保留会话上下文 |
| 历史输入 | 上 / 下箭头 | 快速复用之前输入过的 prompt 或命令 |
| 多行输入 | 按终端默认行为处理 | Codex CLI 没有单独强调一套专属多行输入快捷键 |

## 高频交互命令

除了键盘快捷键，Codex CLI 更常用的是“命令 + 参数”这一套工作方式。下面几条基本覆盖了日常高频场景：

```bash
codex
codex exec "实现一个带重试的 HTTP 客户端"
codex review
codex resume --last
codex fork --last
codex mcp list
```

对应场景如下：

- `codex`：进入交互模式
- `codex exec "..."`：非交互执行一次性任务
- `codex review`：对当前代码进行审查
- `codex resume --last`：恢复最近一次会话
- `codex fork --last`：从最近一次会话分叉新任务
- `codex mcp list`：查看当前 MCP 配置

## 实战建议

- 遇到任务执行偏离预期时，先用 `Ctrl+C` 中断，再用更具体的 prompt 重新描述目标，通常比等它跑完更高效。
- 长会话中频繁用上 / 下箭头复用历史输入，可以减少重复键入。
- 如果只是跑一次命令式任务，优先用 `codex exec "..."`，比进入交互模式再输入更直接。
- 做多分支探索时，优先用 `codex resume --last` 和 `codex fork --last`，比从头重新解释上下文更省时间。
